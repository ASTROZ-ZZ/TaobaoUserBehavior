# 基于用户行为数据的电商转化与商品运营分析

UserBehavior 项目任务书

编写与完善日期：2026-11-26  
项目定位：面向数据分析实习的商业分析项目。以 SQL 指标计算、业务问题拆解、可视化和运营建议为主，简单预测为可选扩展，不开展复杂搜广推算法。

> 本文是本项目的执行方案，不是天池官方竞赛任务书。文中路径均相对于 `UserBehavior/`。本次已完成全量核验与五部分商业分析；结果见 `reports/分析报告.md`，独立核对记录见 results/08_validation/validation.csv 和 independent_validation.csv。

## 1. 项目目标

围绕“用户在哪里流失、哪些人和商品值得优先运营、如何验证改进效果”开展分析，形成可复现的数据处理、SQL 分析和业务报告。

| 核心问题 | 分析内容 | 决策用途 |
| --- | --- | --- |
| 用户何时活跃，购买何时发生？ | 日/小时活跃及购买分布 | 安排运营时段，区分规模与效率 |
| 浏览、收藏、加购与购买如何关联？ | 行为覆盖、顺序转化及未购买路径 | 定位可触达的转化机会 |
| 用户是否持续回来并再次购买？ | 短期留存、购买日频次 | 识别短期持续活跃与回访特征 |
| 哪类用户适合优先运营？ | 活跃度、最近行为、购买频次分层 | 设计分层触达假设 |
| 哪些商品或品类存在转化机会？ | 流量、购买用户与转化效率交叉分析 | 确定商品运营排查优先级 |

项目不预设“转化偏低”或某种策略一定有效。结论必须来自数据；运营建议需要区分观察证据与待验证假设。

正式分析与报告按以下五部分组织：**平台整体经营分析 → 转化漏斗 → 时间分析 → 用户分析 → 商品分析**。数据准备作为前置阶段，业务报告与验证方案作为收尾阶段。下文所有“预期回答”均为研究问题，不是预先确定的结论。

## 2. 数据与使用边界

### 2.1 本地输入

- 原始文件：`data/raw/UserBehavior.csv`。
- 当前检查：文件约 3.4 GiB；前五行符合无表头、逗号分隔、五字段格式。
- 来源：[天池淘宝用户购物行为数据集](https://tianchi.aliyun.com/dataset/649)。
- 公开介绍的主要观察窗口：2017-11-25 至 2017-12-03，规模约一亿条行为。实际行数、时间范围与异常记录需要完整扫描确认。

| 字段 | 解释 | 处理约定 |
| --- | --- | --- |
| `user_id` | 匿名用户 ID | 标识符，不能当作连续数值解释 |
| `item_id` | 匿名商品 ID | 标识符，用于商品聚合与行为匹配 |
| `category_id` | 匿名品类 ID | 不推断其对应的真实品类名称 |
| `behavior_type` | 行为类型 | `pv` 浏览、`fav` 收藏、`cart` 加购、`buy` 购买 |
| `timestamp` | Unix 秒级时间戳 | 先按 UTC 解析，再转为 Asia/Shanghai 派生日期与小时 |

### 2.2 解释边界

1. 日志没有价格、支付金额、订单 ID 或购买数量，不能计算真实 GMV、客单价、利润、订单数，也不能将一条 `buy` 日志直接称为一笔订单。
2. 没有真实曝光日志，不能计算曝光点击率；商品浏览到购买指标应明确命名为“浏览用户购买转化率”等。
3. 观察窗口约九天，只研究短期回访与购买行为；不能据此判断长期流失、长期客户价值或稳定的季节规律。
4. 首次在窗口中出现不等于新注册用户；窗口内首次购买不等于历史首购。数据结论仅代表该样本与观察窗口，不外推为淘宝全平台指标。
5. 没有实验分组与营销触达记录，不能宣称真实 A/B 实验、因果提升或营销增量。允许交付待实施的实验设计。
6. 缺少金额维度，不使用传统 RFM 的 Monetary 评分。可以使用最近行为、购买日频次、活跃天数等可解释的行为分层。

## 4. 分阶段任务与验收

### 阶段 A：数据核验与清洗

**任务**

- 记录源文件字节数、SHA-256、总行数、解析失败数量、实际时间范围和行为取值。
- 检查字段缺失、ID 异常、时间异常、完全重复、商品与品类对应关系。
- 将时间转换为北京时间，统计主要观察窗口外记录；原始文件保留，异常记录单独计数并记录处理理由。
- 完全相同的日志不能未经判断就视为错误。比较保留与去重后的规模和关键指标，确定主口径并记录敏感性。
- 产出事件明细、用户日聚合、商品日聚合；后续有需要再增加用户—商品聚合。

**验收**：原始行数能够与保留、排除、解析失败等互斥处理类别核对；清洗规则、数据类型和时区明确；提供质量报告与可重复执行的处理入口。

### 阶段 B／第一部分：平台整体经营分析

**业务问题**：样本用户规模、浏览强度与购买行为整体如何？每日变化由用户规模还是行为频次驱动？

建立如下指标体系，分别输出全窗口与每日结果。所有比率写明时间范围、粒度、分子、分母和去重键。

| 必交指标 | 基础定义 | 解释要求 |
| --- | --- | --- |
| PV | `pv` 行为记录数 | 浏览次数，不是曝光次数 |
| UV | 期间发生任意行为的去重用户数 | 本项目 UV 指活跃用户，另列浏览 UV |
| 浏览 UV | 期间发生 `pv` 的去重用户数 | 与整体活跃 UV 分开 |
| DAU | 自然日发生任意行为的去重用户数 | 使用北京时间 |
| 人均浏览量 | PV / 浏览 UV | 明确分母，不与 PV / 活跃 UV 混用 |
| 收藏人数 | 出现 `fav` 的去重用户数 | 不等于收藏日志数 |
| 加购人数 | 出现 `cart` 的去重用户数 | 不等于加购日志数 |
| 购买人数 | 出现 `buy` 的去重用户数 | 不等于订单数 |
| 用户购买率 | 购买人数 / 同期活跃 UV | 属于期间购买占比，不要求先浏览后购买 |
| 日活趋势 | 按日展示 DAU | 同时对照 PV、购买人数和用户购买率 |

补充四类行为次数与占比，描述“用户规模—浏览强度—购买覆盖”的关系。日 UV 不能相加代替区间 UV，分组比率不能直接取算术平均代替整体比率。

**验收**：指标字典、核心 SQL、全窗口指标卡、每日经营表与日活趋势图；零分母返回空值或明确标记，图表注明日期、单位和口径。标题可沿用“平台整体经营分析”，结论须注明这是样本行为概况，未包含收入与利润。

### 阶段 C／第二部分：转化漏斗

**业务框架**：浏览 → 收藏／加购 → 购买，同时保留浏览后直接购买路径。收藏与加购可以重叠，用户不必经历所有环节。

#### C1. 行为覆盖与顺序漏斗

- 先统计四种行为用户数及交集，作为行为覆盖分析；不将不满足先后条件的四个用户数直接画成递减漏斗。
- 主顺序分析以同一用户、同一商品为匹配单位，观察浏览→购买、浏览→收藏→购买、浏览→加购→购买。
- 三条浏览起始路径以首次合格浏览为起点，要求后续行为发生在该次浏览后的 24 小时内；中间行为与购买满足严格时间顺序。直接购买路径指该窗口内购买前未观察到收藏或加购，不代表用户历史上从未做过这些行为。
- 另以首次合格收藏、首次合格加购为起点，分别计算未来 24 小时同商品购买率，用于比较两类意向行为的后续购买关联。
- 每条路径中同一用户—商品只计一次。各路径可能共享样本和购买，不能直接相加；如展示互斥路径，先定义重叠分配规则。
- 使用严格后续时间；同秒多行为无法确定顺序，单独计数。仅纳入起点后仍有完整 24 小时可观察的样本，避免末端转化率被低估。

#### C2. 必须回答的问题

| 问题 | 分析办法 | 结论边界 |
| --- | --- | --- |
| 浏览到购买转化率多少？ | 完整随访的浏览用户—商品对中，24 小时内购买的比例 | 与全平台用户购买率分开 |
| 哪一步流失最严重？ | 对各条路径分别报告节点人数/对数、条件转化率、未转化规模 | 同时看比例与规模；未收藏或未加购不自动等于购买流失 |
| 加购后为何没有购买？ | 对比已转化与未转化样本的品类、历史活跃、行为时段等 | 定位差异，价格、库存等原因只能待验证 |
| 收藏和加购哪个对购买关联更强？ | 对照相同随访长度下的后续购买率，并分品类、活跃群体比较 | 原始率差异可能来自人群组成，不代表因果效果 |
| 不同用户群体转化率是否不同？ | 使用路径起点以前的活跃、购买历史分层，展示各群分母和转化率 | 不用未来购买标签划组后证明其更容易购买 |

加购与收藏比较时补充“仅收藏、仅加购、两者都有”的描述；这类分组若使用全窗口行为，应明确只用于画像，不能用于前瞻预测。

分析已转化样本的等待时间，报告中位数及分位数，并注明未转化样本未计入该等待时间分布。至少调整一次转化时间窗检查主要结论是否稳定。

**验收**：行为覆盖图、带分母与时间窗的分支漏斗、流失对比表、收藏与加购对比、分群转化分析和敏感性检查。所有漏斗节点注明是去重用户还是用户—商品对，不混用单位。

### 阶段 D／第三部分：时间分析

**业务问题**：用户何时浏览、何时购买？高流量时段是否同时具有高转化效率？

必做内容：小时级四类行为分布、每日活跃、每日购买人数及购买行为次数、工作日与周末比较、每小时转化分析。

| 时间指标 | 定义 | 用途 |
| --- | --- | --- |
| 小时行为次数 | 每个自然小时内各行为的日志数 | 识别行为高峰 |
| 小时活跃/购买人数 | 每个自然小时内的活跃/购买去重用户数 | 区分规模与次数 |
| 小时购买用户占比 | 同一自然小时购买人数 / 活跃人数 | 当小时购买覆盖，不是浏览后转化 |
| 浏览起点小时转化率 | 按浏览起点的小时分组，计算完整 24 小时内同商品购买的用户—商品对占比 | 比较不同时段浏览的后续转化效率 |

- 先按“日期×小时”输出，汇总 0–23 点时，购买占比按各小时用户数之和/活跃用户数之和计算，单位是用户—小时，不冒充区间去重用户率；顺序转化按合格起点样本数加权。
- 工作日与周末天数不同，行为规模同时给出日均值；比率使用对应总分子/总分母。说明九天样本不能证明稳定的周末效应。
- 浏览高峰与购买高峰是否错位由结果决定，不能预写“20–22 点最高”。购买发生小时与此前浏览起点小时属于不同口径，需分别展示。
- 将结果转为运营时段假设，例如高活跃时段承接流量、历史加购人群的触达时段，并说明需要线上验证。

**验收**：每日趋势图、24 小时行为曲线、日期×小时热力图、小时转化率图、工作日/周末对照表及运营时段建议。

### 阶段 E／第四部分：用户分析

#### E1. 短期留存与 Cohort

- 以窗口内首次活跃日作为 Cohort 起点 D0，计算 D1、D3、D7 精确日留存；D1 指起点之后一天，避免“Day 1”计数歧义。
- 第 N 日留存 = 该 Cohort 中 D0+N 当日仍活跃人数 / 起始 Cohort 人数。
- 仅展示具有完整随访的格子，不可观察的单元格留空，不填 0；另标 Cohort 初始规模。
- 区分精确第 N 日留存与未来 N 天内回访率。窗口首次活跃用户不等于新注册用户。

#### E2. 窗口内再次购买与购买间隔

- 按购买活跃天数区分未购买、单日购买、多日购买用户；另列 `buy` 日志次数，不把它称为订单数。
- 主再次购买定义为：窗口内首次购买日之后，其他自然日再次出现购买行为。比较不同 Cohort 时采用同长度、可完整观察的随访，例如未来三天。
- 以每个用户各购买日的首次购买时间代表该日购买，计算相邻购买日之间的时间间隔，输出均值、中位数、四分位数、样本用户数和间隔数。
- 均值同时明确是所有可观察间隔的均值，还是先求用户均值后再平均；主口径采用前者，并补充中位数，避免少数长间隔主导。
- 输出称为“窗口内可观察的再次购买间隔”，不解释成长期平均复购周期；只有多日购买且两次均被观察到的用户贡献间隔，短窗口存在截断与选择偏差。
- 高频购买按购买活跃天数衡量，阈值先看分布再固定，披露阈值与敏感性；同商品再次购买可补充分析。

#### E3. 活跃 × 购买四象限分层

主分层采用用户提供的四象限，不强行使用复杂 RFM。活跃度主指标为活跃天数，购买强度主指标为购买活跃天数；浏览频次、最近活跃及收藏加购作为辅助画像。

| 用户层 | 描述 | 待验证的运营方向 |
| --- | --- | --- |
| 高活跃＋高购买 | 经常访问且多日购买 | 持续服务、交叉品类运营 |
| 高活跃＋低购买 | 经常访问但购买较少或未购 | 拆解加购未购、收藏未购与纯浏览人群 |
| 低活跃＋高购买 | 访问天数较少但购买较集中 | 识别目的性购买及回访机会 |
| 低活跃＋低购买 | 访问少且购买少或未购 | 评估轻量激活与触达覆盖 |

- 活跃阈值以全体用户分布为依据，购买阈值结合购买用户分布与多日购买的业务含义确定。不得直接在包含大量零值的数据上用零中位数把所有用户划为“高购买”。
- 明确阈值、边界值归属和各象限规模；四组互斥、合计覆盖全部用户。某象限为空时如实报告，不为填满图形强改阈值。
- 对照各群人数、占比、PV、购买日频次、收藏加购覆盖及品类偏好。高购买群购买更多是分组定义本身，不作为新的业务发现。
- 全窗口四象限用于描述；如比较后续转化，分层须仅使用观察起点以前的信息，分母与随访长度一致。

**验收**：D1/D3/D7 Cohort 表与热力图、单日/多日购买分布、购买间隔表、高频购买画像、四象限人群表与差异化运营建议。

### 阶段 F／第五部分：商品分析

**业务问题**：哪些商品和品类贡献流量与购买？哪些高流量商品的转化值得优先排查？

| 必做分析 | 交付要求 |
| --- | --- |
| Top 商品、Top 品类 | 分别按浏览规模与购买用户数排名，不使用含糊的单一“Top” |
| 浏览量最高商品 | 同时给出 PV、浏览 UV，区分反复浏览与覆盖人群 |
| 转化率最高商品 | 使用同商品顺序转化口径，展示分子、分母、最小样本门槛 |
| 高流量低转化商品 | 形成有规模依据的优先排查清单 |
| 低流量高转化商品 | 检查样本稳定性后提出扩流验证假设 |
| 品类运营 | 比较品类流量、购买用户、转化与头部集中度 |

- 流量主指标使用浏览 UV；转化主指标使用完整 24 小时随访的浏览用户—商品对购买率。期间购买 UV 与期间浏览 UV 的简单比值不能冒充顺序转化。
- 高低流量、转化阈值依据分布确定并固定；转化排名设置最小样本门槛，调整门槛检查稳定性。品类对比保持一致的去重单位；品类之间的购买用户可能重叠。
- “高流量低转化”表示浏览覆盖较高但观察到的后续购买比例较低，是排查线索，不能直接证明商品吸引点击或购买环节有故障。
- 对价格、详情页、库存、评价、需求错配等解释，只列为候选假设。说明需要补充价格与竞品、页面行为、库存、评价或流量来源等数据，并提出分层对照或实验方案。
- 不用简单相乘直接宣称收益。例如“转化率提升一个百分点可能对应多少新增转化对数”仅可作有假设的情景估算，不能当作实际新增用户、订单或 GMV。

**验收**：商品/品类 Top 表、流量—转化散点图、商品象限分布、高流量低转化排查表、低流量高转化机会表。每条建议按“观察证据—候选原因—所需新增证据—验证动作”呈现。

### 阶段 G：业务报告与验证方案

报告主章节采用上面五部分，另附数据质量与方法说明。围绕“问题—口径—证据—解释—建议—验证”组织，至少形成三条有数据支持的发现；每条建议说明目标人群或商品、覆盖规模、实施动作、核心指标与约束。

设计一个待实施的 A/B 实验：明确假设、目标人群、用户级随机分流、主要指标、护栏指标、样本量所需参数和完整观察期。当前没有真实触达成本、收益或实验样本，不能报告实际 ROI、实验提升；未知参数列为待确定。

## 5. 可选扩展：简单购买倾向预测

完成商业分析主线后再决定是否开展，仅使用逻辑回归等简单可解释方法，不作为必交内容。

- 任务示例：观察前五天行为，预测接下来两天是否购买；必须先核实实际有效日期。
- 特征仅使用观察截止点以前的数据；历史购买频次、活跃天数、最近行为间隔、加购收藏次数等均从历史窗口计算。
- 使用较早预测时点开发，较晚时点评估；具体日期和重叠情况需要披露。同一预测时点的数据不能随机拆分后声称时间外泛化。
- 对照总体购买率、简单规则与模型，报告 PR-AUC、ROC-AUC 和固定覆盖率下的 Precision、Recall、Lift；调参不使用最终测试标签。
- 不将预测高分等同于营销可被说服的人群，不把模型排序效果称为营销增量。
- 若九天窗口无法提供合理的开发与测试样本，则保留为探索性结果，不强行证明模型有效。
